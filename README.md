# ระบบเข้าเวรผ่าน Discord (Local Database)

บอท Discord สำหรับระบบเข้าเวร บันทึกข้อมูลลงฐานข้อมูล **SQLite ในเครื่อง** แบบเรียลไทม์ — ไม่ต้องพึ่ง Google Sheets, Google Cloud หรือ Service Account อีกต่อไป ทุกอย่างทำงานอยู่ภายในบอทเอง

## โครงสร้างโปรเจกต์

```
duty-bot/
├── config.json                  # role แอดมิน, ห้อง log, รายชื่อหน่วยงาน
├── .env.example                 # ตัวอย่างไฟล์ตั้งค่า (คัดลอกเป็น .env)
├── data/
│   └── duty.db                  # ไฟล์ฐานข้อมูล SQLite (สร้างอัตโนมัติเมื่อรันครั้งแรก)
└── src/
    ├── index.js                 # จุดเริ่มต้นของบอท
    ├── deploy-commands.js       # สคริปต์ลงทะเบียน slash commands
    ├── commands/
    │   ├── register.js          # /สมัคร
    │   ├── checkin.js           # /เข้าเวร
    │   ├── checkout.js          # /ออกเวร
    │   ├── hours.js             # /ชั่วโมง
    │   └── admin/
    │       ├── onDuty.js        # /คนเข้าเวร
    │       ├── clearDuty.js     # /ล้างเวร
    │       ├── editTime.js      # /แก้เวลา
    │       ├── addHours.js      # /เพิ่มชั่วโมง
    │       ├── subHours.js      # /ลดชั่วโมง
    │       ├── weeklySummary.js # /สรุปสัปดาห์
    │       └── exportData.js    # /ส่งออกข้อมูล (สำรองข้อมูลเป็นไฟล์ CSV ส่งในดิสคอร์ด)
    └── utils/
        ├── db.js                 # เชื่อมต่อ + สร้างตาราง SQLite ทั้งหมด
        ├── time.js                # คำนวณเวลา/ชั่วโมง รองรับเข้าเวรข้ามวัน
        ├── embeds.js              # สร้าง Discord Embed
        └── permissions.js         # เช็คสิทธิ์แอดมิน + ส่ง log
```

## ขั้นตอนติดตั้ง

### 1. ติดตั้ง dependencies

```bash
npm install
```

> ใช้ `node:sqlite` ซึ่งเป็นโมดูล SQLite ที่**มากับ Node.js เองตั้งแต่ 22.5 ขึ้นไป** ไม่ต้องติดตั้งไลบรารีฐานข้อมูลแยก และไม่ต้องคอมไพล์ native module (ไม่ต้องมี Visual Studio Build Tools / node-gyp เหมือน `better-sqlite3`) ต้องใช้ **Node.js เวอร์ชัน 22.5 ขึ้นไป** — เช็คด้วย `node -v`
>
> เวลารันอาจเห็นข้อความ `ExperimentalWarning: SQLite is an experimental feature` ซึ่งเป็นแค่คำเตือน ไม่กระทบการทำงาน

### 2. สร้าง Discord Bot

1. ไปที่ https://discord.com/developers/applications → New Application
2. ไปที่แท็บ **Bot** → กด Reset Token เพื่อได้ `DISCORD_TOKEN`
3. เปิด **Privileged Gateway Intents** → เปิด `SERVER MEMBERS INTENT`
4. ไปที่แท็บ **OAuth2 → URL Generator** เลือก scope `bot` และ `applications.commands` พร้อมสิทธิ์ที่จำเป็น (Send Messages, Embed Links, Attach Files) แล้วใช้ลิงก์เชิญบอทเข้าเซิร์ฟเวอร์
5. คัดลอก **Application ID** เป็น `DISCORD_CLIENT_ID` และ ID เซิร์ฟเวอร์เป็น `DISCORD_GUILD_ID` (เปิด Developer Mode ใน Discord แล้วคลิกขวาที่เซิร์ฟเวอร์ > Copy Server ID)

### 3. ตั้งค่าไฟล์ .env

```bash
cp .env.example .env
```

`.env` ตอนนี้มีแค่ค่าที่เกี่ยวกับ Discord ล้วนๆ ไม่มีค่า Google อีกต่อไป:

```
DISCORD_TOKEN=...
DISCORD_CLIENT_ID=...
DISCORD_GUILD_ID=...
DB_PATH=./data/duty.db
```

### 4. ตั้งค่า config.json

- `adminRoleIds` — ใส่ Role ID ของแอดมิน (คลิกขวาที่ role ในเซิร์ฟเวอร์ > Copy Role ID)
- `logChannels` — ใส่ Channel ID ของห้อง log แต่ละประเภท (ถ้าไม่ตั้งค่าจะข้ามการส่ง log อัตโนมัติ)
- `departments` — รายชื่อหน่วยงานที่จะให้เลือกตอน `/สมัคร`

### 5. ลงทะเบียน Slash Commands

```bash
npm run deploy
```

### 6. รันบอท

```bash
npm start
```

เมื่อรันครั้งแรก ไฟล์ `data/duty.db` และตารางทั้งหมดจะถูกสร้างอัตโนมัติผ่าน `utils/db.js` — ไม่ต้องเตรียมอะไรล่วงหน้า

## แผงเข้าเวรแบบปุ่ม (Duty Panel)

บอทมีระบบ "แผงเข้าเวร" เป็นข้อความปักหมุดพร้อมปุ่ม 🟢 **เข้าเวร** / 🔴 **ออกเวร** และแสดงสถานะแบบเรียลไทม์ว่าตอนนี้มีใครกำลังเข้าเวรอยู่บ้าง (จำนวนคน + รายชื่อ) เหมือนภาพตัวอย่างที่ให้มา

**วิธีติดตั้ง:**
1. ให้แอดมิน (มี role ตาม `adminRoleIds` ใน `config.json`) รันคำสั่ง `/แผงเข้าเวร` ในห้องที่ต้องการ (หรือระบุห้องผ่าน option `ห้อง`)
2. บอทจะโพสต์ข้อความแผงเข้าเวร (3 embed ซ้อนกัน: หัวข้อ, คำอธิบาย, สถานะ) พร้อมปุ่ม แล้วบันทึกตำแหน่งข้อความไว้ในตาราง `duty_panel`
3. ทุกครั้งที่มีคนกด 🟢 เข้าเวร หรือ 🔴 ออกเวร (หรือใช้คำสั่ง `/เข้าเวร`, `/ออกเวร`, หรือแอดมินใช้ `/ล้างเวร`) บอทจะแก้ไข (edit) ข้อความแผงเข้าเวรให้ตรงกับสถานะล่าสุดโดยอัตโนมัติ — ไม่ต้องรีเฟรชเอง
4. เวลากดปุ่ม ผู้ใช้จะได้รับข้อความตอบกลับแบบ ephemeral (เห็นคนเดียว) เหมือนตอนใช้สแลชคอมมานด์ทุกประการ (แจ้งข้อผิดพลาดถ้ายังไม่สมัครสมาชิก, เข้าเวรซ้ำ, ยังไม่ได้เข้าเวร ฯลฯ)
5. หากบอทออฟไลน์แล้วกลับมาออนไลน์ใหม่ จะซิงก์แผงเข้าเวรที่ปักไว้ให้ตรงกับฐานข้อมูลล่าสุดโดยอัตโนมัติตอนบอทพร้อมทำงาน (`ready` event)
6. ต้องการย้ายแผงไปห้องอื่น หรือรีเซ็ตดีไซน์ ก็แค่รัน `/แผงเข้าเวร` ซ้ำอีกครั้ง — จะโพสต์ข้อความใหม่และให้บอทติดตามข้อความนั้นแทน (ข้อความเก่าจะไม่ถูกลบอัตโนมัติ ลบเองได้ตามต้องการ)

## ระบบ Log เข้าเวร/ออกเวร

ทุกครั้งที่มีการเข้าเวร/ออกเวร ไม่ว่าจะผ่านการ**กดปุ่มบนแผงเข้าเวร**หรือพิมพ์คำสั่ง `/เข้าเวร` `/ออกเวร` บอทจะส่ง log แบบเดียวกันไปที่ห้อง log ที่ตั้งไว้เสมอ เพื่อให้แอดมินตรวจสอบย้อนหลังได้ง่าย

**วิธีเปิดใช้งาน:**
1. สร้างห้องข้อความสำหรับเก็บ log (เช่น `#log-เข้าเวร`) แล้ว copy Channel ID
2. ใส่ Channel ID ลงใน `config.json` ที่ `logChannels.เข้าเวร` และ `logChannels.ออกเวร` (จะใช้ห้องเดียวกันหรือแยกห้องกันก็ได้)
   ```json
   "logChannels": {
     "สมัคร": "1234567890",
     "เข้าเวร": "1234567890",
     "ออกเวร": "1234567890",
     "แอดมิน": "1234567890"
   }
   ```
3. ถ้าไม่ใส่ค่า (ปล่อยเป็น `"ใส่_CHANNEL_ID"`) บอทจะข้ามการส่ง log ห้องนั้นไปเงียบๆ ไม่ error

**ข้อมูลที่อยู่ใน log แต่ละรายการ:**
- รูปโปรไฟล์ + ชื่อ Discord ของผู้ทำรายการ (author ของ embed)
- ชื่อในเกม, หน่วยงาน, เวลาที่เข้า/ออกเวร, จำนวนชั่วโมงรวม (กรณีออกเวร)
- ผู้ใช้แบบ mention (`<@id>`) กดแล้วเด้งไปหาโปรไฟล์ได้ทันที
- footer บอกช่องทางที่ใช้ทำรายการ เช่น `ผ่าน: ปุ่มแผงเข้าเวร` หรือ `ผ่าน: คำสั่ง /เข้าเวร` เพื่อแยกให้ชัดว่าทำผ่านปุ่มหรือพิมพ์คำสั่ง

นอกจากนี้ยังมี:
- `/สมัคร` → log เข้าห้อง `logChannels.สมัคร`
- คำสั่งแอดมินทุกตัว (`/ล้างเวร`, `/แก้เวลา`, `/เพิ่มชั่วโมง`, `/ลดชั่วโมง`) → log เข้าห้อง `logChannels.แอดมิน` พร้อมชื่อแอดมินที่ดำเนินการ
- `/ส่งออกข้อมูล` → export log ทั้งหมดในตาราง `duty_log` เป็นไฟล์ `.csv` แนบในดิสคอร์ด สำหรับดูประวัติย้อนหลังแบบละเอียดหรือทำรายงาน

## หลักการออกแบบที่ควรรู้

- **ป้องกันเข้า/ออกเวรซ้ำ**: เช็คสถานะล่าสุดใน `duty_log` ก่อนทุกครั้ง (query `WHERE discord_id = ? AND checkout_at IS NULL`)
- **รองรับข้ามวัน**: ชั่วโมงคำนวณจาก timestamp เต็ม (ISO datetime) ไม่ใช่แค่เวลานาฬิกา จึงข้ามเที่ยงคืนได้ถูกต้อง
- **ชั่วโมงวันนี้/สัปดาห์/เดือน**: คำนวณสดจาก `duty_log` ทุกครั้งที่ใช้ `/ชั่วโมง` ด้วย SQL query ตรง เพื่อความแม่นยำสูงสุด ส่วนตาราง `summary` จะถูกอัปเดตเมื่อแอดมินรัน `/สรุปสัปดาห์` หรือเมื่อระบบรีเซ็ตรายสัปดาห์อัตโนมัติทำงาน

### ระบบสรุป/รีเซ็ตรายสัปดาห์อัตโนมัติ (`src/utils/weeklyReset.js`)

- ยอด "สัปดาห์นี้" คำนวณจากสัปดาห์แบบ ISO (จันทร์–อาทิตย์ เวลาไทย) อยู่แล้ว ดังนั้นพอขึ้นสัปดาห์ใหม่ตัวเลขจะเริ่มนับจาก 0 ให้เองโดยอัตโนมัติ **ไม่มีการลบข้อมูลเก่าออกจาก `duty_log`** ประวัติเก่ายังอยู่ครบสำหรับดูย้อนหลัง/ส่งออก CSV
- ทุกๆ 1 นาที บอทจะเช็คว่าสัปดาห์ที่เพิ่งจบไปนั้นเคยถูกสรุปไปแล้วหรือยัง (เก็บสถานะไว้ในตาราง `bot_state`) ถ้ายัง จะสรุปยอดของสัปดาห์ที่ผ่านมาให้อัตโนมัติ แล้วโพสต์แจ้งในห้องตาม `logChannels["สรุปสัปดาห์"]` ในไฟล์ `config.json` (ต้องตั้งค่า channel id เอง ไม่งั้นจะข้ามการโพสต์แต่ยังบันทึกลง `summary` ตามปกติ)
- ออกแบบให้ตรวจสอบด้วย "สัปดาห์ล่าสุดที่จบไปแล้ว" ไม่ใช่เวลาปัจจุบันเป๊ะๆ เพื่อให้ทำงาน "ตามทัน" ได้เองแม้บอทจะออฟไลน์อยู่พอดีตอนเที่ยงคืนวันจันทร์
- **การปรับชั่วโมงมือ**: `/เพิ่มชั่วโมง` และ `/ลดชั่วโมง` จะเพิ่มแถวพิเศษใน `duty_log` (สถานะ `ปรับเพิ่ม`/`ปรับลด`) เพื่อให้นับรวมในชั่วโมงอัตโนมัติโดยไม่ต้องแก้ยอดตรงๆ — ตรวจสอบย้อนหลังได้ง่ายผ่าน query
- **หลายหน่วยงาน**: กำหนดผ่าน `departments` ใน `config.json` จะกลายเป็นตัวเลือก (choices) ในคำสั่ง `/สมัคร` อัตโนมัติ
- **สำรองข้อมูล**: เนื่องจากไม่มี Google Sheets ให้เปิดดูสดๆ อีกแล้ว แนะนำให้ตั้ง cron/scheduled task รันคำสั่งสำรอง (backup) ไฟล์ `data/duty.db` เป็นระยะ หรือใช้ `/ส่งออกข้อมูล` เพื่อดึงข้อมูลออกมาดูเป็นระยะ

## ต่อยอดในอนาคต (ตามสเปก)

โครงสร้างปัจจุบันรองรับการเพิ่มระบบลา/อนุมัติได้ง่าย โดยแนะนำให้:
1. เพิ่มตาราง `leave_requests` ใน `utils/db.js`
2. เพิ่มคำสั่ง `/ลา`, `/อนุมัติ`, `/ปฏิเสธ` ในรูปแบบเดียวกับโค้ดที่มีอยู่
3. ใช้ `utils/permissions.js` และ `utils/embeds.js` ชุดเดิมได้ทันที

## หมายเหตุด้านความปลอดภัย

- ห้าม commit ไฟล์ `.env` และ `data/duty.db` ขึ้น git (มี `.gitignore` เตรียมไว้ให้แล้ว) เพราะไฟล์ฐานข้อมูลมีข้อมูลสมาชิกจริง
- แนะนำให้สำรอง (backup) ไฟล์ `data/duty.db` เป็นระยะ เนื่องจากข้อมูลทั้งหมดอยู่ในเครื่องที่รันบอทเท่านั้น ไม่มีสำเนาบนคลาวด์เหมือน Google Sheets เดิม
